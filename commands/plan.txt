Load the `dox-project-context` skill using `skills_tool` with `action: load, skill_name: "dox-project-context"`, then load the `planning-and-task-breakdown` skill using `skills_tool` with `action: load, skill_name: "planning-and-task-breakdown"`. Follow both workflows.

Read the existing spec at `tasks/spec.md`, the relevant codebase sections, and the applicable `AGENTS.md` chain for the areas likely to change. Then:

1. Enter plan mode — read only, no code changes
2. Identify the dependency graph between components
3. Slice work vertically (one complete path per task, not horizontal layers)
4. Write tasks with acceptance criteria, touched paths, applicable DOX scopes, and verification steps
5. Add checkpoints between phases
6. Present the plan for human review

Save the plan to tasks/plan.md and task list to tasks/todo.md. Treat tasks/todo.md as the DOX-governed lifecycle todo artifact. Perform DOX closeout before finishing. If planning changes durable workflow, ownership, artifacts, or verification, update the nearest owning `AGENTS.md`.
